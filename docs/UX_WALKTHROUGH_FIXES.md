## P1

### P1-1 "开始新的学习"是空动作

- **改法**：侧栏按钮不再是 `router.push("/?new=1")`，改为真正 `POST /api/sessions` → 跳 `/s/{id}?new=1`；
  会话页读到 `new=1` 后把焦点落到输入框，并清掉 URL 参数。按钮加了 `creating` 状态（"正在新建…"）。
  `AppShell.tsx` `newSession()` / `SessionView.tsx` 自动聚焦。
- **验证**：`tests/ui-check.mjs` 三项断言——跳到会话页、会话数 +1、`document.activeElement` 是 textarea。

### P1-2 提示/解析标记被永久记在题上

- **改法**：这两个标记的语义改成"只对这一次作答有效"。
  - 新增 `resetExerciseFlags()`：提交成功（`graded && !duplicate`）后在同一请求里清空 `hint_used_at / solution_viewed_at / hint_count`。
    提交时仍按当时的标记计入证据——所以"用过提示那次"不会被洗白。
  - 新增 `POST /api/exercises/[id]/reset`，「再做一次」同时清服务端标记（此前只重置前端展示）。
- **验证**：冒烟"提示只对本次作答有效"5 项：取提示 → 作答（`usedHint=true`）→ reset → 再答对（`usedHint=false`）
  → 知识点 `independentCorrect` 确实 +1（旧行为卡住不动）。单测覆盖标记读写与清零。

### P1-3 复习「练一练」每点一次多开一个会话

- **改法**：`POST /api/sessions` 在 `mode=review && reviewItemId` 时先查是否已有"未产生任何作答"的同条目会话
  （`findOpenReviewSession`），有则直接返回并带 `reused: true`；前端提示"继续上次这条复习"。
  条件不要求 `message_count > 0`——刚建好、消息还在路上的会话也会被复用。
- **验证**：冒烟连续两次创建同一 reviewItemId，第二次 `reused === true` 且 id 相同；单测覆盖"空壳会话也复用 / 作答后不再复用"。

## P3

| 项 | 改法 |
|---|---|
| 计划重复不合并 | `save_plan` 先按标题查重：命中则在原路线追加缺少的步骤，不再新建同名路线（`findPlanByTitle` / `appendPlanItems`） |
| 两个「给我提示」 | 输入区快捷条改名「给点思路」，与练习卡内的「给我提示」区分 |
| 复制按钮只在 hover 显示 | 移动端常显（`opacity-60`），桌面端仍 hover 出现，另加 `focus-visible` |
| 图标按钮缺 aria-label | 小结 / 档案 / 删除 / 材料删除 / 计划完成 均补 `aria-label` |
| 目标学习徽章竖排 | 徽章 `shrink-0 whitespace-nowrap`，标题让位截断 |
| 流式滚动抢占 | 只在距底 < 160px 时自动跟随；用户上滑阅读时不再被拽回 |
| 材料大小显示 0 KB | `<1KB` 显示字节（`81 B`），其余 KB/MB 保留一位小数 |
| 历史只搜标题 | 搜索框标注「按标题搜索（不含消息内容）」，不假装全文检索 |
| 导航无 aria-current | 桌面与移动导航的活动项都加 `aria-current="page"` |

## 未改（明确保留）

- **计划步骤与学习证据不联动**：AI 生成的步骤没有绑定知识点（`concept_id` 为空），无法做"答对自动完成"。
  当前选择手动口径并把文案改准；要做证据驱动，需要先让 `save_plan` 为每一步登记/关联知识点。
- **历史全文检索**：需要 FTS5 + 中文 trigram 索引与迁移，属于独立改动，本次只把能力边界写清楚。
- **"学这一步"每次新建会话**：与 P1-3 同类问题，但步骤天然是一次性任务，暂未做复用。
