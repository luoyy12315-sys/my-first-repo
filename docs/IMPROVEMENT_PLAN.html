02

产品判断

它已经是什么

  • 一个诚实的单机导师。没模型就说没模型，评不了就说评不了，答案不下发——这三点比大部分“AI 学习产品”都硬。
  • 一个证据系统。BKT、审计、快照、复习队列都在，删除会话还能正确重放。
  • 一个内容生成器。8 个白名单工具把模型输出约束成可交互组件，而不是一坨 Markdown。

它现在还不是什么

  • 不是一个“每天想打开”的工具。首页能开始学习，但没有“今天该做什么”的确定答案。
  • 不是一个能读懂教材的助教。材料被塞进上下文，但回答没有引用，用户无法验证依据。
  • 不是一个会因材施教的导师。它知道你“没掌握”，但不太知道你“为什么没掌握”。
护城河判断：通用聊天工具可以讲得一样好，甚至更好；它们缺的是“跨会话记住你错过什么、并按错因换一种方式再测你”。所以功能建议一律围绕这条线，凡是不能增强“证据 → 诊断 → 复测”的，优先级都往后放。

04

详细建议

每项都给出场景、做法、代码落点与可验收标准。落点尽量复用已有结构，不新造轮子。

A · 把证据变成诊断

A1错因结构化 + 错题本价值 高成本 中批次一
场景：用户在「导数」上连错三次，档案显示“需要巩固”。但他到底是公式记错、还是审题漏条件、还是计算符号错？现在系统不知道，模型也不知道，只能泛泛地“换个讲法”。

做法

  • attempts 增加 error_type：概念混淆 / 计算失误 / 审题遗漏 / 表述不全 / 知识缺口。
  • 客观题由判题器直接推断（多选漏选 → 审题遗漏；数值量级错 → 单位/量级；填空近似 → 表述不全）；开放题由评阅模型在 JSON 里返回。
  • 知识点详情聚合“Top 错因”，复习建议按错因生成不同文案。
  • 上下文注入从“状态 + p 值”升级为“最近 3 次错因 + 当时选了什么”。

代码落点

src/lib/db/schema.ts（attempts 加列）
src/lib/learning/exercise.ts（判题侧推断）
src/app/api/attempts/route.ts（写入）
src/lib/ai/prompt.ts（注入错因）
src/app/library/page.tsx（错因展示）

验收：同一知识点连续 3 次“概念混淆”后，复习理由与提示词里出现该错因；答对一次后错因不再主导；每类错因至少有 1 个单元用例。注意：错因只用于“怎么教”，不得反过来直接改掌握度——证据优先的原则不能破。
A2结构化复习会话价值 高成本 低批次一
场景：复习页点“练一练”，现在只是拼一句话：“来做一个短复习：知识点「X」……先用一两道题测我”。模型可能先讲十分钟，也可能出三道超纲题，系统完全无法约束。

做法

  • 创建会话时传结构化参数：{ mode:"review", focusConceptId, reviewItemId }，而不是只传一句自然语言。
  • 上下文明确约束：本轮先 present_exercise（同型 1 道 + 变式 1 道），答完再决定讲不讲；拿不到证据就不算复习完成。
  • 会话与复习条目绑定：产生有效作答后自动把条目置为 done，并刷新 next_review_at；无作答退出则保留条目。
  • 会话结束时给一句“这次复习解决了什么 / 还差什么”，写回条目备注。

代码落点

src/app/review/page.tsx（改成传 id）
src/app/api/sessions/route.ts（接收 focus）
src/lib/db/schema.ts（sessions 加 focus_concept_id / review_item_id）
src/lib/ai/prompt.ts（复习模式约束）
src/app/api/attempts/route.ts（回写 review_items）

验收：从复习进入后，首个教学组件必须是练习；作答后该条目从队列消失且 next_review_at 延后；直接退出会话则条目保留。成本低的原因：队列、会话、证据三张表都已存在，只差把“自然语言约定”换成“结构化字段”。
A3单条证据作废与重算价值 高成本 低批次一
场景：模型出的一道题本身有歧义，用户答错被记了证据；或者开放题评阅明显误判。现在只能整条删除知识点，或者忍着。档案的“可追溯”变成了“只能信”。

做法

  • evidence 增加 voided 与 void_reason，软作废而不是物理删除，审计记录保留。
  • 知识点详情列出每条证据（时间、题目、对错、是否用提示），提供“这条不算”与原因。
  • 复用现成的 recomputeConceptAggregates() 重放剩余证据；作废动作写 concept_events。
  • 若作废后该知识点证据归零，状态回到“尚未接触”，而不是留着旧 p 值。

代码落点

src/lib/db/schema.ts（evidence 加列）
src/lib/db/repo.ts:129（重算函数已存在）
src/app/api/evidence/[id]/route.ts（新增 DELETE）
src/app/library/page.tsx（证据列表 + 作废）

验收：作废一条证据后 p 值与状态按剩余证据重算、快照新增一条、审计写明“用户作废”；作废最后一条后回到 untouched。注意：软作废的数据仍参与导出与审计，不参与掌握度与复习调度。
A4掌握度校准视图价值 中成本 高批次三
场景：系统说“p(掌握)=0.88”，用户下次做新题还是错。BKT 参数是否适合这个人？没有人知道。

做法

  • 每次“新题首次作答”视为一次校准点：记录预测 p 与实际对错。
  • 按知识点/主题统计 Brier 分数或分桶正确率（0.6-0.7、0.7-0.8…），显示“高估/低估”。
  • 校准长期偏差时，允许个人化调整 pG / pS（先只展示，不自动改）。

代码落点

mastery_snapshots（已有时间序列）
attempts（首答标记）
新增 /api/calibration
library 或独立小页

验收：至少 20 个首答样本后展示分桶图；数值与手工 SQL 一致。为什么放后面：样本不足时图表只会制造噪音，先把 A1/A2 的证据密度做起来。

B · 让材料真正参与教学

B1材料引用可溯源价值 高成本 中批次二
场景：用户上传课件后问“第三章说的那个条件是什么”，回答看起来对，但没有任何来源标记。用户无法判断这是课件内容，还是模型的通用知识——这正是“不编造”承诺最该被看见的地方。

做法

  • 注入材料片段时附带稳定 id，要求模型在正文用 [[cite:chunkId]] 标注依据。
  • 服务端解析标记：只接受本轮真实注入过的 id，其余丢弃并记一条降级提示（防编造引用）。
  • 消息渲染为可点击的来源卡片：材料名 + 段落标题 + 片段预览，点击跳到材料页对应位置。
  • 没有材料依据时明确不标，不用“据资料”这类模糊措辞。

代码落点

src/lib/ai/prompt.ts（注入 id + 引用规则）
src/lib/types.ts（MessagePart 加 citations）
src/app/api/chat/route.ts（解析与白名单校验）
src/components/Markdown.tsx（渲染来源卡片）

验收：问材料相关问题至少出现 1 个有效引用；伪造的 chunk id 被过滤且不留死链；未上传材料时不出现引用 UI。注意：引用校验必须在服务端做，不能信任模型输出。
B2从材料段落直接出题价值 高成本 中批次二
场景：用户上传了 40 页讲义，想“就这一节练 3 道题”。现在只能回到聊天框描述，模型还得自己找段落，经常跑偏。

做法

  • 材料页每个切片提供“就这段出题”，可选题型与数量（1-3 道）。
  • 后台用该切片 + 现有 exerciseInputSchema 生成，走与聊天工具相同的校验与落库路径（答案仍只存服务端）。
  • 出题结果进入一个轻量会话（或材料详情），可直接作答并计入知识点。
  • 生成失败时明确提示“这段内容不足以出题”，不硬凑。

代码落点

src/app/api/materials/[id]/exercise/route.ts（新增）
src/lib/ai/tools.ts（复用 createExercise 路径）
src/app/materials/page.tsx（入口）

验收：生成的题目提交前响应不含答案；作答能正常判题并写证据；不足 50 字的切片给出明确失败提示。

C · 学习节奏与可控性

C1今日计划：给一个 10 分钟的确定答案价值 高成本 中批次二
场景：用户打开首页，看到四个示例问题、最近会话、薄弱点、复习建议——信息很多，但没有一句“现在开始做什么”。选择成本就是流失成本。

做法

  • 首页顶部给一张“今天”卡片：到期复习 N 个 → 取 1 个；最薄弱 1 个；预计 10 分钟。
  • 一键开始，走 A2 的结构化会话；完成后回填“今天已完成”，不搞积分与排行榜。
  • 没有到期任务时，给“继续上次”或“试一个新主题”，不硬造任务。

代码落点

src/app/api/home/route.ts（返回 todayPlan）
src/app/page.tsx（卡片 + 一键开始）
复用 refreshReviewQueue / listWeakConcepts

验收：有到期条目时优先推荐复习；完成后当天不再重复推荐同一条；无数据时显示空态而非假任务。
C2题目反馈与“换一题”价值 高成本 低批次二
场景：模型出的题太难、太简单，或者答案本身有问题。用户唯一的选择是硬做或跳过，系统学不到任何东西。

做法

  • 练习底部加三个轻量反馈：太简单 / 太难 / 这题有问题（可附一句说明）。
  • “这题有问题”将该题排除出掌握度与复习（复用 A3 的作废逻辑），并降低同类题的生成倾向。
  • “换一题”：同知识点、不同题型重新生成，优先交错练习（上次单选，这次填空/判断）。
  • 反馈进入提示词，作为下一题难度的依据。

代码落点

新增 exercise_feedback 表
src/components/blocks/ExerciseBlock.tsx（入口）
src/lib/ai/prompt.ts（难度与题型偏好）
src/app/api/exercises/[id]/retry/route.ts（新增）

验收：反馈可持久化；“有问题”的题不再计入证据；换题与原题题型不同且知识点一致；连续两次“太简单”后下一题难度上调。
C3长会话大纲 + “换一种讲法”价值 中成本 中批次三
场景：一次会话 60 条消息，用户想回到“刚才那个模拟器”或“第三道题”，只能疯狂滚动。模型讲了一遍没听懂，用户只能重新打字“换个说法”。

做法

  • 会话侧栏按 block 生成大纲：练习 / 图表 / 模拟器 / 小结，点击滚动定位并高亮。
  • 助手消息提供“换一种讲法”：带上 intent: "rephrase"，提示模型换表征（例子/图示/对比），而不是复述。
  • 移动端大纲收进抽屉，不占正文宽度。

代码落点

src/components/chat/SessionView.tsx（大纲）
src/app/api/chat/route.ts（intent 参数）

验收：大纲项与页面 block 一一对应且可跳转；rephrase 请求在提示词中带明确意图，不新增会话；移动端无横向溢出。
C4导出学习记录价值 中成本 低批次三
场景：一周学完，想复盘或发给同学；现在只能截图，题目、答案、反馈、掌握度变化全散在界面里。

做法

  • 会话页提供“导出为 Markdown”，包含：讲解正文、题目、我的作答、判题反馈、掌握度变化、来源引用。
  • 未作答的练习只导出题干，绝不导出答案。
  • 浏览器打印样式即可得到 PDF，不引入额外依赖。

代码落点

新增 /api/sessions/[id]/export
src/app/s/[id]/page.tsx（按钮）
src/app/globals.css（打印样式）

验收：导出内容与界面一致；未作答题目无答案字段；Markdown 结构有快照测试。
C5全局搜索价值 中成本 中批次三
场景：“上次那道关于机会成本的题挺有意思”——现在只能按会话标题找，找不到就只能翻历史。

做法

D · 成本与可靠性

D1用量与成本面板价值 中成本 低批次三
场景：用户用自己的 API Key，月底才发现账单翻倍；usage_log 记了 tokens 与延迟，但界面上一个字都没露。

做法

  • 设置页增加“用量”：今日 / 7 天 / 30 天的 tokens、请求数、成功率、P50/P95 延迟。
  • 价格表可配置（每百万 token），估算费用；不做硬编码的厂商价格。
  • 可设月度预算，超 80% 提示一次，不阻断使用。

代码落点

usage_log（已有）
新增 /api/usage/summary
src/app/settings/page.tsx

验收：统计值与 SQL 手算一致；无数据时显示空态；价格未配置时只显示 tokens 不显示金额。
D2主模型 / 快模型分级价值 中成本 中批次三
场景：生成提示、开放题评阅、会话标题这些短任务，和主讲共用同一个贵模型。成本高，且这些任务对模型能力要求并不高。

做法

  • 设置页增加“快模型”一档（可留空，回退主模型）。
  • 提示生成、开放题评阅、标题、摘要走快模型；主讲与出题走主模型。
  • usage_log 记录实际使用的模型，D1 面板按模型拆分。

src/app/api/settings/ai/route.ts

验收：未配置快模型时行为不变；配置后提示请求的 usage 记录为快模型；失败自动回退主模型并留日志。
D3提示词评测集（改提示词前的安全网）价值 高成本 中批次一
场景：A1、B1 都要改系统提示词。这类改动没有编译错误，却可能让模型突然“先讲十分钟再出题”或“把答案写进正文”。现在只能靠肉眼碰运气。

做法

  • 建 20-30 条黄金用例：该出题 / 该只回答 / 该拒答（涉及答案） / 该引用材料 / 该承认不知道。
  • npm run eval 调真实模型跑一遍，断言“工具选择 + 答案不泄露 + 是否引用”，输出通过率。
  • 无 API Key 时跳过并明确提示，不假装通过；结果存 JSON 便于对比版本。
  • 把“答案绝不出现在正文”做成硬断言：扫描模型文本是否包含标准答案。

代码落点

tests/eval/cases.json
tests/eval/run.mjs
package.json scripts.eval
（复用 provider.completeJson / streamChat）

验收：用例覆盖 5 类意图；答案泄露用例为 0 通过即失败；每次改 prompt.ts 前后各跑一次并记录差异。为什么排第一批：它是后续所有提示词改动的护栏，先有它再动 prompt。
05

不建议做

下面这些不是“以后再说”，是现在就不该做——它们会让产品偏离“可信证据”这条主线，并持续消耗维护成本。

排行榜 / 积分 / 徽章

单机学习工具没有社交比较对象；把内在动机换成外部积分，通常换来的是刷题而不是学会。

社区 / 分享动态

需要账号、审核、存储与隐私合规，和“本地单用户、数据不出机器”的定位直接冲突。

AI 数字人 / 语音陪聊

成本高、延迟高，对“掌握一个知识点”没有增量；真正缺的是诊断，不是拟人。

一上来就上向量库

本机材料量级用 FTS5 + 关键词足够；向量库会引入嵌入成本、索引同步与召回不可解释的问题。

多租户 SaaS 化

要重做鉴权、隔离、计费与运维；当前 SQLite 单文件架构会全部推倒。除非换商业模式，否则不做。

继续堆工具类型

8 个工具已覆盖教学表征；再加只会让模型选择困难、前端维护面变大。先把现有工具用对。

06

怎么衡量有没有变好

别用“消息数”和“使用时长”自欺——它们只能证明用户在用聊天框，不能证明学会了。

指标定义方向数据来源
北极星：每周独立正确知识点一周内产生“独立、未看解析”的正确作答的不同知识点数上升evidence + attempts
激活率首次会话 24 小时内完成 ≥1 次作答的用户占比上升sessions + attempts
复习完成率到期复习条目中，产生有效作答的比例上升review_items
7 天复测保持率复习后 7 天内同知识点新题仍答对的比例上升evidence 时间序列
提示依赖率正确作答中使用提示的比例下降attempts.used_hint
看解析率作答前查看解析的比例下降exercises.solution_viewed_at
题目作废率被标记“这题有问题”的题目占比下降（先升后降）exercise_feedback
每知识点成本tokens 成本 / 产生证据的知识点数下降usage_log

单机应用没有服务端埋点，以上指标直接从本地库算即可；不要为此引入第三方分析 SDK。

07

落地顺序

按依赖关系排，不按“看起来酷”排。每批都有明确的完成定义，做完一批再开下一批。

批次包含完成定义依赖
第一批
把闭环补完		A3 证据作废 · A1 错因 · A2 结构化复习 · D3 评测集复习从“建议”变成“有始有终的一次会话”；错因能被记录、展示、注入；改提示词有回归护栏无，全部基于现有表
第二批
让材料与练习好用		B1 引用 · B2 材料出题 · C2 题目反馈/换一题 · C1 今日计划回答能溯源；材料能直接练；坏题能被剔除；首页能给出“今天做什么”B2 依赖 B1 的片段 id；C1 依赖 A2 的结构化会话
第三批
长期使用		C3 大纲/换讲法 · C4 导出 · C5 搜索 · D1 用量 · D2 双模型 · A4 校准长会话可导航、学习记录可带走、成本可见、模型可分级C5 与 B1 共用 FTS/片段索引；A4 需要足够首答样本
如果只能做一件事：做 A2。它不需要新表、不需要新模型能力，只把复习页那句自然语言换成结构化字段，就能把“复习队列”变成“复习行为”。这是当前投入产出比最高的一处。
