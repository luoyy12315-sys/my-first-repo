03

问题清单

按影响排序。P1 会直接让核心动作失效或污染学习证据；P2 是明显摩擦；P3 是可访问性与细节。

P1 · 核心动作

P1-1“开始新的学习”在首页点击等于没点AppShell.tsx:77 · page.tsx:64
复现：首页 → 点侧栏“开始新的学习” → URL 变为 /?new=1，会话数 4 → 4，document.activeElement 仍是 BUTTON，输入框没有获得焦点。

观察

  • 直接访问 /?new=1 时输入框会聚焦，说明逻辑本身存在。
  • 从首页点击时，路由只是 query 变化，首页组件不重新挂载，useEffect 不重跑，聚焦逻辑被跳过。
  • 从会话页点击时会跳回首页并聚焦——所以“有时候灵、有时候不灵”，更难排查。

为什么不符合预期

按钮写着“开始新的学习”，用户预期是“出现一个新的学习空间”。实际既不建会话、也不清空输入框、也不聚焦，唯一变化是地址栏多了一个参数。它和导航“学习”是同一个去处，属于同一动作的两个入口。

影响：用户第一次想“新建”就撞空；老用户会误以为应用卡了。
建议（二选一）：① 删掉这个按钮，让“学习”导航承担唯一入口；② 让它真的新建：POST /api/sessions → router.push(/s/{id})，空会话进入后自动聚焦输入框。若保留 query 方案，改用 useSearchParams 监听 new 参数，而不是只在挂载时读一次。
P1-2“用过提示 / 看过解析”被永久记在题上，重做永远不算独立repo.ts:1304-1330 · attempts/route.ts:44
复现：练习点“给我提示” → 选正确答案提交 → 点“再做一次” → 不带提示再提交。接口返回 usedHint: true，知识点 independentCorrect 从 2 到 2（没涨），p 从 0.817 涨到 0.921。

观察

  • exercises.hint_used_at / solution_viewed_at 一旦写入就不清空。
  • 提交时用“客户端传值 || 服务端标记”，服务端标记是永久真。
  • “再做一次”只重置了前端展示状态，服务端仍认为你用过提示。

为什么不符合预期

提示的作用范围应该是“这一次作答”。用户重做时明明是独立完成的，却被永久判为“借助提示”；更糟的是 p 值仍在涨，档案里会出现“掌握度上升、独立正确数不涨”的矛盾数据。

影响：同一道题一旦用过提示就永远无法贡献“独立正确”证据；看过一次解析则后续所有重做都不计入掌握度。这是证据系统在自我污染。
建议：每次评分提交成功后，在同一事务里清空该题的 hint_used_at / solution_viewed_at / hint_count；或把 flags 快照写进 attempts，提交后重置题目级标记。“再做一次”要同时重置服务端标记。补一条集成测试：用提示 → 提交 → 重做 → 独立正确数必须 +1。
P1-3复习“练一练”每点一次就多开一个会话，没有“继续”review/page.tsx:43-57
复现：复习页有 1 条建议 → 点“练一练”进入会话 → 返回 → 再点一次。会话数从 7 变成 9，出现两条同名“复习：机会成本”。

观察

  • 每次点击都无条件 POST /api/sessions，不检查是否已有未完成的复习会话。
  • 进入会话但未作答时，复习条目仍然是 open，所以列表还显示“练一练”。
  • 侧栏“最近”里很快堆满同名条目，无法分辨哪次是当前。

为什么不符合预期

“练一练”是一次连续动作：开始 → 做题 → 完成。现在它只负责“开始”，既不锁定条目，也不提供返回继续，用户很容易开一堆半途而废的会话。

影响：复习队列越用越乱，证据分散在多个半截会话里。
建议：按 reviewItemId 查“未完成的复习会话”，有则跳回并提示“继续上次复习”；没有才新建。进入后把条目置为 accepted 并从 open 列表移除；产生有效作答或会话结束时置 done。

P2 · 明显摩擦与误导

P2-1“设定新目标”不进入目标模式，用户要点两次plan/page.tsx:83, 98
复现：计划页点“设定新目标” → 跳到首页 /?new=1，模式选择仍停在“自由学习”，页面没有任何目标输入表单。

观察

按钮只是 router.push("/?new=1")。首页默认 mode = "free"，不会读取任何“目标”意图。

为什么不符合预期

用户点“设定新目标”，期待的是“目标填写界面”。现在他到了首页，还得自己发现要再点一次“目标学习”，然后才知道该说什么。

建议：带意图跳转：/?new=1&mode=goal，首页读取参数设置模式并把占位文案换成“例如：两周内搞定期末线代”；或者直接在计划页开一个目标表单，提交后再创建会话。
P2-2“学这一步”不推进进度，完成靠一个没文字的小圆圈plan/page.tsx:66, 137
复现：计划页点“学这一步” → 创建会话、步骤变“进行中” → 返回计划页，进度仍是 0/4；要标记完成，得点标题为“标记为完成”的圆形序号按钮。

观察

  • “学这一步”只改 in_progress，不判断是否真的学了。
  • 完成动作是手动勾选，按钮本身是一个没有可见文案的序号圆圈。
  • 页面文案写“进度只由你真实的完成动作计算”，但系统并不校验任何学习证据。

为什么不符合预期

“学”与“完成”是同一件事的两半，现在被拆成两个互不相干的动作。用户学完回来，进度条不动，会以为没生效；而“真实完成动作”的说法又在暗示系统会自动判断。

建议：两种口径选一个并写清楚：① 证据驱动：该步骤关联知识点产生有效作答后自动置 done；② 手动口径：把文案改成“完成后手动勾选”，并给序号按钮加可见的“标记完成”文字或复选框。当前是“文案说自动、交互靠手动”，两头不靠。
P2-3侧栏“最近”标题不刷新，重命名只改主区AppShell.tsx:51-54 · SessionView.tsx:294
复现：会话自动命名后，主区标题已是“从零开始教我机会成本…”，侧栏仍显示“新的学习”；手动重命名为“UX 验收-重命名测试”，主区变了，侧栏仍是旧标题。

观察

侧栏只在 pathname 变化时重新拉取会话列表。重命名是 PATCH 请求，pathname 没变，所以侧栏永远慢一拍，直到刷新或跳页。

为什么不符合预期

同一个会话在屏幕上出现两个名字，用户会怀疑“到底改没改成功”。自动命名后显示“新的学习”尤其伤，因为那是最需要被识别的时刻。

建议：把会话列表放进全局 store（或 SWR），重命名/新建/删除后调用 mutate；低成本方案是在 touchSession 成功后派发 window.dispatchEvent(new Event("sessions:changed"))，侧栏监听刷新。
P2-4首页同一条复习建议出现两次page.tsx:230-260
复现：首页顶部“今天 · 约 10 分钟 · 复习：机会成本”与下方“复习建议 · 机会成本”，文案、概念、按钮完全同源。

观察

“今天”卡从 review[0] 取第一条，“复习建议”列表又把同一批 review 全量渲染，没有排除已被今天卡消费的那条。

为什么不符合预期

用户会以为有两件事要做，点进去发现是同一个知识点。首页本该降低选择成本，结果制造了重复项。

建议：今天卡消费首条后，列表从第二条开始；没有剩余时显示“今天只有这一件，做完就收工”。或者合并成一个区块：今天卡为主，下面只显示“其他 N 条”。
P2-5材料删除没有确认，点了就删文件materials/page.tsx · materials/[id]/route.ts
复现：材料页点垃圾桶 → 无弹窗，列表立即清空，GET /api/materials 返回 []，磁盘文件同步删除。

观察

删除按钮只有一个图标，点击直接 DELETE；没有确认、没有撤销、没有说明会连带删除切片。

为什么不符合预期

会话删除都有确认弹窗，材料删除反而没有。材料是用户自己的文件，误触成本更高。

建议：加确认弹窗，写明“将删除文件与 N 个文本切片，不可恢复”；或改软删除并提供回收站。至少给删除按钮加 aria-label="删除材料" 与二次确认。
P2-6删除会话弹窗的说明已经过期SessionView.tsx:530-560
复现：打开会话删除弹窗，文案写“掌握度分数不会自动回滚（已有快照保留可追溯）”，但删除并勾选证据后，知识点状态实际会按剩余证据重算。

观察

  • “掌握度不会回滚”与 recomputeConceptAggregates 的实际行为相反。
  • “会话内的对话、练习和组件状态会被删除”：默认只删对话与组件，exercises/attempts 只有勾选“同时删除证据”才会删。

为什么不符合预期

这是唯一一处向用户解释“删除会发生什么”的地方，两句话都不准确。用户会基于错误预期做决定。

建议：按当前实现重写：默认删除对话、组件与草稿，保留题目/作答/证据；勾选后删除证据并重算掌握度（会回落），审计与快照保留。文案要和代码一起改，别再让文案跑在实现前面。
P2-7会话里的“材料”是单向跳转，没有回程SessionView.tsx:524 · Composer.tsx:134
复现：会话输入区点回形针 → 跳到 /materials；页面没有“返回刚才的会话”，底部导航也没有当前会话入口，只能靠浏览器后退。

观察

onAttach={() => router.push("/materials")}，没有携带 returnTo，材料页也不知道自己是从会话来的。

为什么不符合预期

用户在会话中途想补一份材料，上传完最想做的是“回到刚才的对话继续问”。现在他会被丢在一个陌生页面，还要自己找回去。

建议：上传做成会话内弹窗（最顺手）；或跳转时带 ?returnTo=/s/{id}，材料页顶部显示“← 回到对话”，上传成功后自动返回。
P2-8未配置模型时仍能发送，报错后没有“去设置”chat/route.ts:76-89
复现：全新实例未配模型 → 输入“从零开始教我导数” → 创建会话“新的学习” → 助手气泡只有一行灰色小字“生成中断 / 模型服务未配置”，没有链接或按钮。

观察

  • 首页有醒目的黄色警告带，但进入会话后提示降级成一行灰字。
  • 输入框仍可输入，快捷条仍在，用户会以为可以继续。
  • 错误气泡没有 CTA，用户得自己点侧栏“设置”。

为什么不符合预期

这是首次启动最常见的路径。产品自己说“没有模型就不假装教学”，那就应该把“去配置”做成唯一显眼动作，而不是让用户先失败一次。

建议：未配置时禁用输入区并显示主按钮“去设置模型”；错误气泡内嵌同样的链接；或干脆在会话页顶部复用首页的警告条。已有 AiWarning 组件，复用它即可。

05

先修哪五个

如果要排一个最短期、最能减少“这什么鬼”的清单，我会按这个顺序。

顺序事项级别为什么先修
1让“开始新的学习”真的新建会话（或删掉它）P1用户遇到的第一个“新建”入口，不能是空动作
2提交后清空提示/解析标记P1不改，重做永远不算独立，证据系统持续失真
3复习会话按条目复用，并锁定/完成条目P1复习是留存核心，不能越用越乱
4删除弹窗与材料删除的确认与文案P2破坏性操作，且当前文案在误导用户
5侧栏标题同步 + 首页复习卡去重P2都是“同一信息出现两次且不一致”，最伤信任
一个统一的设计建议：给“新建学习”定义一个明确的动作契约——创建会话、决定模式、决定上下文（自由/目标/复习/计划步骤），全部通过结构化参数传递，而不是各自拼一句自然语言再跳首页。现在这四种“开始”分散在四个页面，语义各不相同，才是这些问题的共同根源。
06

做得好、别改坏的地方

  • 工作区有明确回程。“返回对话”在左上角，状态自动保存，这是正确的沉浸式设计。
  • 删除会话有确认和证据保留选项。方向对，只是文案需要跟上实现。
  • 答案提交前不下发。走查全程没有在任何响应里看到标准答案。
  • 移动端无横向溢出，底部导航可用。390px 下布局没有崩。
  • 深色模式可用，图表与公式未破。切换后 data-theme=dark 正常生效。
  • 空状态文案诚实。“没有材料也能学”“扫描件需要 OCR，当前不支持”，没有画饼。
