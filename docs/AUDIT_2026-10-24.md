## 0. 一页结论

**核心判断：问题不在"模型讲不好"，而在"一次回复没有做完"。**

模型本身能讲得相当好（复现中借贷记账法一题给出了类比、公式、对照表和记借记贷的规律）。真正的损失发生在管道层：

1. **推理内容被丢弃**。模型把 4000 token 全花在 `reasoning_content` 上，代码只读 `content`，前端拿到空字符串。这不是偶发，是命中预算后的必然结果。
2. **工具调用后不续写**。讲解在调用工具的位置直接截断，用户看到"看两种制度各自怎么记："然后就没了。
3. **工具失败被静默吞掉**。图表校验不通过时返回 `ok:false`，不产生任何提示，用户和模型都不知道发生了什么。
4. **能力缺口被模型"诚实"地暴露**。要饼图给柱状图、要瀑布图给柱状图+表、要 K 线直接空回复——因为协议里根本没有这些图型。

**最该先做的 3 件事（约 4 人日）：**

| 顺序 | 事项 | 解决什么 | 粗估 |
|---|---|---|---|
| 1 | 分离并保留 `reasoning_content`，把输出预算提到 12k–16k，空回复自动重试一次 | 空回复 / 答一半 | 0.5 人日 |
| 2 | 工具执行结果回传模型，允许最多 2 轮续写（含失败修复） | 讲解断在冒号 / 图表静默失败 | 1.5 人日 |
| 3 | 「讲解风格」真正落成设置项 + 「换个讲法」改成结构化表征选择 | 没有自定义风格 | 1.5 人日 |

**紧接着做（约 1 周）：** 图表协议扩容（饼图/瀑布/K线/双轴 + 类目轴）、证据独立性修复、消息分页与部分内容落库。

**明确不建议做：** HTML/iframe 沙箱、现在引入向量库、现在做批次 2 的 CSRF/限流/密钥加密、一次性铺满风格预设矩阵。

- 通用图型（折线/柱状/散点）：**6/10 完全达标**
- 金融专用图型（饼图/瀑布/双轴/K线）：**0/4 达标**

```json
  "reasoningLen": 6233,
  "finish": "length",
  "usage": { "completion_tokens": 4000,
             "completion_tokens_details": { "reasoning_tokens": 4000 } }
}
```

这不是模型"不会画"，是**它在思考阶段就被预算掐断了，而思考内容没有进入任何可见通道**。

1. **模型能力不是瓶颈。** 给它自由，它能讲出类比、公式、表格；给它明确风格，它能照做。
2. **最大的质量损失来自"工具边界截断"。** 第 2 条是最直接的证据：模型显然准备在表格之后继续解释，但管道在工具调用处结束了。

## 3. 根因清单

### 3.1 P0：直接造成你看到的症状（已复现）

#### P0-1 推理内容被丢弃 + 输出预算过低

- 代码：`src/lib/ai/provider.ts:174` 只读 `delta.content`，从不读 `delta.reasoning_content`
- 预算：`src/lib/ai/config.ts:54` 默认 `maxTokens=4000`；`src/lib/ai/provider.ts:114` 传给 `max_tokens`
- 后果：推理型模型在难问题上会把预算全部用于思考，`content` 为空，用户看到"模型这次没有返回可用内容"（`src/app/api/chat/route.ts:213`）
- 影响面：**不只是图表**。任何需要思考的讲解、出题、规划都可能触发

#### P0-2 工具调用后不续写，讲解断在半句

- 代码：`src/app/api/chat/route.ts:191-211` 在文本流结束后串行执行工具，然后直接结束
- 后果：模型"先写引导语 → 调工具 → 准备继续"的结构被截断；复现第 2 条停在冒号
- 附带影响：工具结果（包括失败原因）从未作为 `role:"tool"` 消息回传

#### P0-3 工具校验失败被静默吞掉

- 代码：`src/lib/ai/tools.ts:712` `if (!parsed.success) return { ok: false, ... }`，且不带 `notice`
- 上层：`src/app/api/chat/route.ts:207` 只在 `outcome.notice` 存在时才记日志
- 后果：图表不合法 → 没有任何块、没有任何提示、模型也不会重试。用户只看到"什么都没有"

#### P0-4 图表协议表达不了金融图型

- 代码：`src/lib/blocks/schema.ts:73` 仅 `line | bar | scatter`；`:69` 的 `x` 必须是 `number`
- 工具描述：`src/lib/ai/tools.ts:191` 明确要求"数据必须来自题目条件或可靠计算，不得编造"；`:195` 枚举同样只有三种；`:207` 的 `x` 写死 `number`
- UI 空态：`src/components/blocks/ChartBlock.tsx:63` "不会编造数据来凑一张图"
- 后果：
  - 饼图/瀑布/K线无法表达 → 模型替换成柱状图或拒绝
  - 类目轴/日期轴无法表达 → "1月"只能写成 1
  - 示例数据被劝阻 → "某公司"没有数据时直接拒答（复现第 6 条）

### 3.2 P1：损坏学习数据的正确性（代码确认）

#### P1-1 看解析后可以"洗白"为独立作答

- `src/app/api/attempts/route.ts:135` 每次判定后无条件清空 hint/solution 标记
- `src/app/api/exercises/[id]/route.ts:17-22` 只要有过一次作答，就下发标准答案
- 路径：随便交一次 → 刷新拿到答案 → 再交一次（标记已被清空）→ 记为"独立正确"→ 写入证据、推进复习
- 后果：核心资产"学习证据"失真。对单用户应用来说不是安全漏洞，是**数据自欺**

#### P1-2 判断题空提交可能判对

- `src/lib/learning/exercise.ts:251` 把无法识别的输入一律当 `false`；而 `answer` 允许为 `null`
- 后果：正确答案为"错"时，空提交/乱填都判对

#### P1-3 数值与填空判分过宽

- `src/lib/learning/exercise.ts:33-36` 空字符串被 `Number("")` 解析为 0
- 默认容差 `max(0.001, 1%)` → 百万级答案接受 ±1 万
- 填空只做文本归一（`src/lib/blocks/schema.ts:213-219`）：`"1000.00" ≠ "1000"`，`"50%" ≠ "50"`
- 后果：既可能误判对，也可能误判错

#### P1-4 200 条消息硬上限（当前未触发，但必然触发）

- `src/lib/db/repo.ts:747` `order by seq asc limit 200` 取的是**最旧** 200 条
- `src/app/api/sessions/[id]/route.ts:26` 与 `src/lib/ai/prompt.ts:283` 都走这个默认值
- 后果：约 100 轮后，新消息在页面上"消失"，模型历史永远停在第 187–200 条
- 当前库只有 10 条消息（最长会话 2 条），所以是**潜伏缺陷**

#### P1-5 失败/中止的半段回答不进历史

- `src/lib/ai/prompt.ts:285` 过滤 `status === "error"`
- `src/app/api/chat/route.ts:298-304` 把停止、超时、断网的部分回答写成 `error`
- 后果：屏幕上有的内容，"继续"时模型看不到 → 重复讲或答非所问

#### P1-6 停止/切页的落库竞态

- `src/app/api/chat/route.ts:253` 全文只在结束时一次性落库
- 前端在流结束的 `finally` 里立即重新加载（`src/components/chat/SessionView.tsx:416-423`）
- 后果：停止后可能读到空的 streaming 消息；流式中切换会话，回调可能把 A 的流写进 B 的页面

#### P1-7 上下文与成本不可见

- `usage_log` 只有写入（`src/lib/db/repo.ts:2728`），全仓无读取
- `done` 事件里的 usage 被前端丢弃
- 单轮基础成本约 **4100 prompt tokens**（系统提示词 + 9 个工具定义），历史最多 14×2200 字符
- 后果：用户无法判断"为什么这么慢/这么贵"，也无法做预算控制

## 4. 解决方案

### 4.1 核心：把"一次回复"改成有界编排（P0）

这是所有体验问题的总开关。目标不是"无限 agent 循环"，而是**最多 2 轮、可预算、可中断**的续写。

```
用户消息
  → 组装上下文
  → 第 1 轮：流式生成
       ├─ 解析 content → 增量落库 + SSE 推送
       ├─ 解析 reasoning_content → 独立的 thinking 事件（不入库、不拼进正文）
       └─ 收集 tool_calls
  → 若有工具调用：
       执行工具
       ├─ 成功 → 以 role:"tool" 回传结果摘要
       ├─ 失败 → 以 role:"tool" 回传 zod 错误（含路径）
       └─ 进入第 2 轮，最多续写 2 轮
  → 终止条件：无工具调用 / 达到轮次上限 / 达到 token 预算 / 用户中止
  → 结束前检查：
       finish=length 且 content 为空 → 预算×2 重试一次
       finish=length 且有内容      → 保留内容 + "未讲完"提示
```

**必须同时做的四件事：**

1. **分离推理通道**。`reasoning_content` 只做两件事：驱动一个"思考中…"的界面状态（可选折叠展示），以及用于判断预算是否耗尽。**绝不写进正文、绝不入库、绝不进历史**。
2. **提高输出预算**。默认 12k–16k，并在设置页暴露。教学场景里 4k 明显不够。
3. **空回复自动恢复**。`finish=length && content==""` → 预算翻倍重试一次，并附加"直接给出最终答案，不要展开推理"的临时指令。这是 K 线案例的直接解药。
4. **增量落库**。每 1–2 秒把已生成内容写回一次（或至少在 abort 时写入），状态用 `partial` 而不是 `error`，历史里保留并标注"（上次未讲完）"。

**续写的约束（防止副作用）：**

- 最多 2 轮，总工具调用仍限 5 个
- 续写提示词固定为："工具已展示。用 1–3 句话收尾；不要复述组件内容；不要泄露练习题答案。"
- `present_exercise` / `present_quiz` 不触发续写（此时没有新信息，续写只会啰嗦或泄题）
- `present_chart` / `present_table` / `present_steps` 触发续写，修复"悬空冒号"

### 4.2 讲解风格系统（P0.5，你点名要的）

模型对明确风格指令是敏感的（复现第 4 条已验证），所以这不需要复杂架构。

**数据结构**（`settings` 表，key = `teaching_profile`）：

```json
{
  "preset": "balanced | rigorous | analogy | exam | socratic",
  "subject": "accounting | english | general | custom",
  "verbosity": 3,
  "requireExample": true,
  "requireCheckQuestion": false,
  "customDirective": "（最多 500 字，自由填写）"
}
```

**注入方式**：作为独立的第二条 system 消息，并写明优先级：

> 【教学风格】以下偏好只在不牺牲准确性和安全性的前提下生效。
> 预设：…；学科：…；篇幅：…；必须给例子：…；结尾必须提一个检验问题：…；
> 学生自定义：…

**「换个讲法」改成结构化表征选择**（这是"没有自定义风格"的另一半）：

```
analogy | concrete-case | contrast-table | step-by-step | formula-derivation | socratic | visual
```

- 按钮展开一个小菜单，默认选中"本会话尚未使用过"的表征
- 服务端在会话元数据里维护 `usedRepresentations: string[]`
- 提示词注入："本次必须使用 **对比表**；不要再使用 [类比、案例]。"
- 这比"换一种更直观的讲法"这句固定话术可靠得多，也直接兑现"自定义风格"

**UI 成本**：设置页一张卡片 + 输入框上一个小菜单，不新增页面。

### 4.3 图表协议 v2（P1）

**短期方案（推荐）：扩展现有类型化协议。** 理由是 zod 可校验、渲染可控、失败可回传；不要为了图型数量引入不可控的通用语法。

```ts
chartType:
  | "line" | "bar" | "area" | "scatter"
  | "pie" | "radar" | "waterfall" | "candlestick" | "combo"

// 通用系列
series?: {
  name: string
  type?: "line" | "bar" | "area"   // combo 用
  axis?: "left" | "right"          // 双轴
  points: { x: number | string; y: number; kind?: "delta" | "total" }[]
}[]

// K 线单独表达，避免污染通用点结构
candles?: { label: string; open: number; high: number; low: number; close: number }[]

// 数据性质
dataKind: "real" | "illustrative"
dataNote?: string   // 例如"示意数据，非真实财报"
```

**配套改动：**

- `x` 支持字符串 → 类目轴、日期轴、"1月"、"资产/负债"直接可画
- 允许示意数据，但必须显式标注 `dataKind: "illustrative"`，UI 显示"示意数据"徽章。这比"一律禁止编造"更符合教学场景，也解决了"某公司"被拒答
- 工具描述同步改写：**"题目给出数据用 real；教学举例可用 illustrative，但必须标注"**
- 校验失败 → 回传 zod 错误，模型自动修一次（复用 4.1 的续写轮）
- 渲染器：饼图/面积图用 recharts 原生能力；瀑布图用堆叠柱 + 透明底；K 线用自定义 SVG/canvas；双轴用 recharts 的双 `YAxis`

**中期方案（如果图型继续膨胀到 10+）：** 换成一个受限的 Vega-Lite 子集，用 schema 校验后交给 vega-lite 渲染。它能一次性覆盖绝大多数金融图，但校验成本和包体积都更高。**现在不要跳。**

**会计专用可视化（P2，先不做）：**

| Block | 用途 | 触发条件 |
|---|---|---|
| `present_t_account` | 丁字账（借/贷两栏） | 复现或真实使用中，"分录/丁字账"请求 ≥3 次/周 |
| `present_statement` | 资产负债表/利润表层级 | 同上 |
| `present_journal` | 多行分录（借/贷对齐） | 同上 |

这三者 recharts 画不出来，需要手写 SVG。**先看真实使用频率再决定**，不要预先造需求。

**Mermaid（可选，低成本）：** 在 `src/components/Markdown.tsx` 给 `language-mermaid` 代码块挂一个动态加载的渲染器（`securityLevel: "strict"`），流程图、会计循环、结账流程立即有解。包体积增加约 1MB，本地应用可接受。

### 4.4 证据与判题正确性（P1）

优先级高，因为它决定"学习档案"是否可信。

1. **独立性与"看过答案"分离**：不要在提交后清空 flag。每次 attempt 记录 `saw_solution_before_submit`、`hint_used`，证据按 attempt 级别判定；`/reset` 必须要求已提交过至少一次，或直接下线该接口。
2. **答案下发加门槛**：`GET /api/exercises/[id]` 只在"已判定且已提交"后返回 `correctDisplay`；未作答时只返回题面。
3. **服务端幂等**：不要依赖客户端 `idempotencyKey`。用 `(exerciseId, attemptSeq)` 或"同一题同一答案 5 秒内去重"。
4. **判断题显式校验**：`answer` 必须是 boolean，或把 `null`/空串直接判为"未作答"而不是 `false`。
5. **数值/填空归一**：支持全角数字、千分位、百分号、单位；空答案不解析为 0；容差改为 `max(绝对最小单位, 0.1%)` 且对百万级答案设上限。
6. **统计口径统一**：抽一个 `conceptStats(conceptId)` 单一函数，首页、档案、计划页全部走它；`distinctExercises` 只保留一种定义。
7. **mastered 衰减**：把 `mastery.ts:192` 的 `stalenessDays` 接进 `progress.ts`，否则课程可以永久 100%。

### 4.5 材料入口（P2）

顺序很重要，先做投入产出比最高的：

1. **图片**：若当前模型支持多模态，直接走"图片 → 模型"（零解析成本）；否则再接 OCR
2. **.pptx**：解压读 XML，无需重依赖
3. **.doc**：明确不支持即可（转换成本高、收益低）
4. **向量检索**：等材料块数过千再上 `sqlite-vec`；现在先把 LIKE 的 `limit 400` 改成按命中词数排序后再截断

### 4.6 交互与性能（P1/P2）

- 消息查询改为 `order by seq desc limit N` 后反转，并加 cursor 分页
- 流式渲染对 delta 做 50ms 合批；`Markdown` 用 `memo`；滚动用 `requestAnimationFrame`
- 超时改为空闲超时（15s 无数据 → 中止），而不是 120s 总时长
- 失败消息给"重试"按钮，并允许原地重发
- 设置页加"用量"卡片：本轮/今日/本月 token 与粗估成本，数据直接读 `usage_log`
- 移动端表格外包一层 `overflow-x-auto`，并在 `body` 加 `overflow-x-hidden` 兜底

## 10. 阶段三落地记录（2026-10-24）

阶段三 5 项全部落地。基线提交 `55a6da2`（阶段一/二成果），本次改动均在其后。

### 10.1 证据独立性（P1-1）

**原问题**：提交后无条件清空 `solution_viewed_at` / `hint_used_at`，`GET /api/exercises/[id]` 只要有任何作答就下发标准答案。于是「看解析 → 随便交一次 → 再做一次 → 再交」会被记成独立正确。

**改法**
- `repo.hasRevealedAnswer(exerciseId)`：该题存在 `viewed_solution=1` 或 `is_correct is not null` 的作答，即"答案已下发过"。
- 提交时独立性由服务端推导：`viewedSolution = 客户端自报 || 题目级标记 || 历史已下发`（`src/app/api/attempts/route.ts`）。
- 答案下发门槛：`GET /api/exercises/[id]` 仅在"至少一次已判定作答"时返回 `correctDisplay` / `explanation`；空提交、待评阅的开放题不下发。
- `/reset` 必须已提交过（否则 409），响应新增 `independent` 字段；前端「再做一次」明确提示"重做只作练习记录"。
- 保留提交后清标记（避免"用一次提示终身被标"），但清标记**不再能恢复独立性**。

**验收**：`tests/unit/evidence-independence.test.ts`（4 例）；smoke 新增「再做一次不会恢复独立完成」「重做被识别出答案已下发」「重做不计入独立正确」；真实模型路径实测同上。

### 10.2 判题边界（P1-2 / P1-3）

| 原问题 | 改法 |
|---|---|
| 判断题 `answer=null/空串` 兜底成 `false`，"正确答案是错"时空提交判对 | 空提交（null/空串/空数组/全空白）统一返回 `graded=false`，不计证据；认不出的判断文本也返回未判定，不再兜底 |
| `Number("") = 0`，空答案被当成 0 | `num()` 显式拒绝空串，支持全角、千分位、百分号 |
| 数值题默认容差 1%，百万级等于 ±1 万 | 默认 `min(max(1e-6, |v|×0.1%), 1)`；显式 `tolerance` 仍优先 |
| 填空只做文本归一：`1000.00 ≠ 1000`、`50% ≠ 50` | 两边都能解析成数字时按数值等价比较（严格等价，不放宽成容差）；纯文本仍走原规则 |

验收：`tests/unit/grading-boundaries.test.ts`（13 例）。

| 竞态 | 切换会话/离开页面时 abort 在跑的生成并按 `AI_ABORTED` 收尾（保留已生成内容 + 重试入口）；`load()` 增加"回来时 sessionId 已变则丢弃"守卫 |

**行为变化**：离开页面或切换会话会中止正在进行的生成（旧行为会继续跑完并落库）。取舍是"不留无人消费的生成、不白烧 token"，需要旧行为时删掉卸载时的那处 abort 即可。

## 11. 阶段三之后的调整（按使用反馈）

### 11.1 删除语义统一（三处）

反馈："删除计划时应该把它关联的知识点一起删"。改成三处一致，避免留下只能靠"知识点库"才找得到的孤儿：

| 入口 | 行为 |
|---|---|
| 删计划 `DELETE /api/plans/[id]` | 删计划 + 步骤 + **其独占的知识点与证据**；被其他计划步骤引用的知识点只解除归属，不删 |
| 删课程（计划里的步骤）`DELETE /api/plans/[id]?deleteCourse=` | 同上，范围限定该步骤 |
| 课程内移除知识点 `POST /api/plans/[id]`（removeConcept） | 直接删该知识点与证据（原行为只解除归属）；共享时仍只解除 |

- 实现集中在 `src/lib/db/repo.ts` 的 `deletePlan` / `deletePlanCourse` / `removeConceptFromCourse`：先判断"是否被别的 `plan_items` 引用"，再决定删除还是仅清 `course_id`；删除前解绑 `exercises.concept_id`、`attempts.concept_id`、`sessions.focus_concept_id`，再删 `review_items` 与 `concepts`，最后 `cleanupTopicIfEmpty`。
- 会话、练习、作答记录**保留**（只解绑），历史对话不会因为删知识点而消失；这是有意的取舍，弹窗里写明。
- 弹窗与 toast 给出数量（"课程已删除，同时移除 N 个知识点"）；`/api/concepts/[id]` 的 409 文案补上"在课程里移除会一并删除该知识点"。
- 文档同步：`README.md`、`docs/WORKFLOWS.md`、`docs/ACCEPTANCE_2026-10-23.md` 的删除语义句子。

### 11.2 设置页收敛：讲解风格与联网检索

反馈："预设的和自定义的为啥要放在一起""联网的自定义选项太多，用户配置这个干什么"。结论是**把选择权收回成最少必要的几项**：

**讲解风格**（`src/lib/teaching/profile.ts` 重写）

| 改动 | 说明 |
|---|---|
| 删掉 5 个预设（均衡/严谨/类比/应试/苏格拉底） | 预设本质是一句话的别名，和用户自己写的要求放一起会互相打架 |
| 删掉学科（通用/会计/英语/自定义） | 人不会只学一科；学科专属提示词收益远小于"按学科写一句要求" |

| 卡片折叠 | ~~默认收起，标题行摘要~~ **第二轮改为不折叠**：设置页两张卡片直接展开可见，见 §12 |

**联网检索**（`src/lib/web/*`、`src/app/api/settings/web/**`）

| 改动 | 说明 |
|---|---|
| 主区只留：启用开关 / 服务商 / 地址或 Key / 对话里默认打开 / 保存并测试 | ~~服务商直接决定要填哪一项~~ **第二轮删掉服务商预设，改为自定义 API**，见 §12 |

| 删除 `allowPrivateProvider` | 该字段从未参与实际判断（provider 直连、抓页始终 `allowPrivate:false`），属于"看着能配、其实没用"的开关；本机/内网地址由用户显式填写 provider 地址即生效 |

## 12. 第二轮：风格改成可添加的自定义卡片、联网改成自定义 API

反馈三句，直接翻译成两条设计决定：

1. 「风格和联网不要折叠起来，直接卡片就行」→ 设置页这两块**不再有展开/收起**，进入就是完整卡片。
2. 「一个加号点击添加自定义，提示词和篇幅和选项都在添加自定义的卡片里」→ 讲解风格从"单份配置"变成**多张自定义卡片**，标题行右上角「添加风格」，每张卡片自带描述、篇幅与两个选项，同一时间只有一个「使用中」。
3. 「联网我不要预设，我要可以自定义 api 的」→ 删掉 SearXNG / Tavily / Brave 三个内置适配器，换成**一个通用 HTTP 搜索接口**。

### 12.1 讲解风格：多张卡片 + 单选生效

| 改动 | 说明 |
|---|---|
| 数据模型 | settings 新增 `teaching_styles`（数组，最多 8 个）与 `teaching_active_style`（当前生效 id，空=默认讲法）；每项 `{id, name, directive, verbosity, requireExample, requireCheckQuestion}` |
| 交互 | 标题行「添加风格」→ 内联卡片编辑（名字 / 你希望我怎么讲 ≤500 字 / 篇幅滑杆 / 举例 / 讲完提问 / 注入预览）；列表卡片显示名字、摘要与「使用中」徽标，可「使用」「改用默认」「编辑」「删除」 |
| 生效规则 | 只注入当前使用中的那一张；没有使用中的就完全不注入，和旧默认行为一致 |
| 迁移 | 老的 `teaching_profile` 在首次读取时转成一张名为「我的风格」的卡片；内容全默认则不建卡片、不注入 |
| 上限 | 8 个，超出返回 400 并提示先删；删除使用中的风格时顺延到剩下的第一个，没有则回到默认讲法 |
| 理由 | 用户会为不同场景准备不同讲法（平时 / 考前），单份配置要么反复改、要么互相覆盖；卡片化后才能"存着备选" |

实现：`src/lib/teaching/profile.ts`（纯数据 + 提示词）、`src/lib/ai/teaching-profile.ts`（持久化 + 迁移）、`src/app/api/settings/teaching/route.ts`（`GET` 列表 / `POST {action:create|update|delete|activate}`）。

### 12.2 联网检索：一个通用 HTTP 接口

| 改动 | 说明 |
|---|---|
| 删掉服务商适配 | `SearXNG / Tavily / Brave` 三个适配器与 `provider/baseUrl` 字段整体移除；`getProvider()` 换成 `searchWeb(cfg, input)`，不再按厂商分支 |
| 主区（直接可见） | 启用开关 / 接口地址（完整 URL）/ 调用方式 GET·POST / API Key / 认证请求头（整行，如 `Authorization: Bearer {{apiKey}}`）/ 对话里默认打开 / 保存并测试 / 测试当前设置 |
| 高级（折叠） | GET 的查询参数名、POST 的请求体模板（`{{query}}` `{{maxResults}}` `{{apiKey}}`）、结果数组路径、标题/链接/摘要字段、最大来源、超时、缓存、会话上限、域名名单、清空缓存 |
| 自动识别 | 结果路径留空时依次尝试 `results` / `data` / `items` / `web.results` / `data.results` / `data.items` / `organic` / `hits`，最后取"顶层对象里第一个对象数组"；字段名留空按常见名字猜；没有 `http(s)` 链接的结果直接丢弃 |
| 测试接口 | 支持传入未保存的草稿；`query` 用中文短语；成功返回延迟、采用条数与前 3 条标题/域名，失败返回错误码 + 建议（鉴权/限流/超时/连不上/响应读不懂） |
| 认证回显 | 服务端永不回显 Key 与认证头，只回 `keyMasked` / `hasAuth`；输入框留空=不修改，另有「清除 Key 与认证头」明确动作 |
| 理由 | 预设只能覆盖"我们想到的服务"，换个自建服务或服务商改接口就得改代码；描述"怎么发请求、怎么读结果"之后，任何返回 JSON 的搜索 API 都能接 |

### 12.3 一并处理的细节

- `POST` 模式的请求体模板在保存时就会校验：替换占位符后必须是合法 JSON，否则返回 400（避免"存进去了但每次检索都失败"）。

- 刷新/重新打开设置页后，认证头与 Key 输入框清空并提示"已配置，留空不修改"。
- 卡片顺序保持不变：模型服务 → 讲解风格 → 联网检索 → 用量 → 数据。

## 15. 侧栏搜索与折叠、下拉菜单统一、输入框去方框

**输入框**

## 18. 侧栏对齐 ChatGPT：三组列表、行内图钉与三个点、折叠后软件图标就是展开按钮

反馈："ChatGPT 是点那个折叠之后折叠按钮也没有了，那个软件图标就会变成折叠按钮功能；鼠标悬停在会话条的时候右边出现三个点和置顶符号；三个点菜单有重命名、置顶、删除、移至计划；会话列表分置顶、计划、最近三部分；计划条悬停也有三个点和置顶，菜单是重命名、置顶、计划详细、删除。"

### 18.1 数据与接口

- 迁移 `20261024_sidebar_pins`：`sessions.pinned_at`、`plans.pinned_at`（可空时间戳，`null` = 未置顶）；只加列不复写数据，老库自动补齐
- `PATCH /api/sessions/[id]` 新增 `pinned?: boolean`；`PATCH /api/plans/[id]` 新增 `action: "pin"` + `pinned`
- 置顶只写 `pinned_at`，**不动 `updated_at`**，避免一置顶就把会话顶到「最近」最前面
- `SessionSummary` / `PlanDTO` 增加 `pinnedAt`，列表接口直接返回

### 18.2 侧栏结构

- 三组，按顺序：**置顶**（有置顶才出现）→ **计划**（每个计划可展开，展开列出关联对话，标题右侧显示条数）→ **最近**（未归入计划的对话，最多 12 条）
- 置顶的会话/计划只出现在「置顶」组，不在下面的组里重复
- 计划展开状态记在 `localStorage["lumina-sidebar-open-plans"]`；第一次用（本机没记过）时，有对话的计划默认展开
- 会话行悬停：右侧出现**图钉 + 三个点**（默认隐藏日期等，留白干净）；图钉直接置顶/取消置顶
  - 三个点菜单：重命名 / 置顶（或取消置顶） / 移至计划 / 删除
- 计划行悬停：同样的图钉 + 三个点
  - 三个点菜单：重命名 / 置顶（或取消置顶） / 计划详细 / 删除
- 点计划行（或左侧箭头）展开/收起；没有关联对话的计划直接进计划详情
- 折叠后：**不再单独留折叠按钮**，软件图标本身就是展开按钮（`aria-label="展开侧边栏"`）；展开态才有「收起侧边栏」
- 行内菜单靠窗口底部时自动向上翻（`OverflowMenu` 新增 flip 判断），不会被侧栏滚动容器裁掉
- 默认的「更多」文字去掉，紧凑按钮只保留读屏名称（`ariaLabel`）

### 18.3 弹窗与危险操作

- 重命名：会话/计划共用，回车即保存，失败在弹窗内提示
- 移至计划：列出所有计划（附「N 门课程 · N 个对话」），已在计划里的对话可以选「不归入计划」；无限学习的对话移入计划时必须选一门课程（并转成目标学习）
- 删除会话：确认文案说明「消息和练习一起删掉，删了不能恢复」
- 删除计划：确认文案说明「课程和知识点一起删掉，删了不能恢复；对话和材料只解除关联」——和 `deletePlan` 的实际语义一致
- 删除/重命名/置顶/移动后广播 `sessions:changed` / `plans:changed`，侧栏、主区、历史与计划页同步刷新
